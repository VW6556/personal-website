VS Code 在 Linux 無法輸入中文

使用 IBus Chewing（新酒）輸入法時，Chrome 等軟體正常，但 VS Code 完全無法切換到中文輸入的排查紀錄與 Lesson Learned。

Ubuntu 24.04 LTS VS Code Snap IBus Chewing Snap 隔離問題 已解決 2026-04-08

問題現象

可以輸入中文

  • Google Chrome
  • Firefox
  • GNOME Terminal
  • 其他 GTK 原生應用

無法輸入中文

  • VS Code（Snap 安裝版）

按下輸入法切換鍵後，VS Code 內完全無反應，只能輸入英文。

系統輸入法狀態

  • IBus 1.5.29 正常執行
  • ibus-engine-chewing 正常
  • 環境變數均已設定

排查過程

確認系統 IBus 環境變數
GTK_IM_MODULE=ibus、QT_IM_MODULE=ibus、XMODIFIERS=@im=ibus 均已在 /etc/environment 設定正確。排除環境變數遺漏的可能。
確認 IBus daemon 運行狀態
ibus-daemon 與 ibus-engine-chewing 均在正常執行。IBus 本身沒有問題。
發現：VS Code 是 Snap 安裝版本
確認 which code 指向 /snap/bin/code，安裝版本為 Snap（/snap/code/232/）。
根本原因：Snap 內部 GTK IM 模組缺少 IBus 支援
檢查 ~/snap/code/common/.cache/immodules/immodules.cache，發現 Snap 捆綁的 GTK 模組清單中完全沒有 im-ibus.so。 Snap 的沙箱隔離機制使其使用內建的 GTK 函式庫，而非系統版本，因此即使系統安裝了 IBus GTK 模組，Snap 內的 Electron 也無法載入它。
解法：改裝官方 .deb 版本
移除 Snap 版，改用 Microsoft 官方 apt repository 安裝 .deb 版。.deb 版使用系統 GTK 函式庫，可正確載入 im-ibus.so，中文輸入立即恢復正常。

根本原因詳解

Snap 沙箱隔離 × GTK IM 模組
Snap 為了可攜性，將所有 GTK 函式庫打包在套件內部（/snap/code/*/usr/lib/），並使用自己的 GTK immodules 快取。這份快取是在 Snap 封裝時預先產生的，不包含系統後來安裝的輸入法模組（例如 ibus-gtk3）。
比較項目Snap 版.deb 版
GTK 函式庫來源Snap 內建系統 /usr/lib/
immodules 快取~/snap/code/common/.cache/immodules/（固定）系統動態查找
im-ibus.so 可用性無有（來自 ibus-gtk3）
中文輸入無法使用正常
更新維護自動（Snap Store）透過 apt

完整解決步驟

1
移除 Snap 版 VS Code 
sudo snap remove code

使用者設定位於 ~/.config/Code/，移除 Snap 後不會被刪除，.deb 版安裝後可直接沿用。

2
加入 Microsoft 官方 apt repository 
wget -qO- https://packages.microsoft.com/keys/microsoft.asc \
  | gpg --dearmor \
  | sudo tee /etc/apt/trusted.gpg.d/microsoft.gpg > /dev/null

sudo sh -c 'echo "deb [arch=amd64] https://packages.microsoft.com/repos/code stable main" \
  > /etc/apt/sources.list.d/vscode.list'
3
安裝 .deb 版 VS Code 
sudo apt-get update
sudo apt-get install -y code
4
驗證安裝路徑並重新開啟 
which code
# 應顯示 /usr/bin/code（非 /snap/bin/code）

重新啟動 VS Code，測試 IBus Chewing 中文輸入是否正常。

重新開啟 VS Code 後即可正常切換 IBus Chewing 並輸入中文，問題完全解決。

Lesson Learned

Snap 不等於原生

Snap 套件的沙箱隔離有助於可攜性，但會切斷與系統 GTK 生態系的整合。凡是需要深度系統整合（輸入法、字型、主題）的應用程式，優先選擇 .deb 或 apt 版本，而非 Snap。

排查輸入法問題的起點

遇到「A 軟體可輸入中文，B 軟體不行」時，先確認：

  1. 兩個軟體的安裝方式是否相同
  2. 檢查 immodules 快取是否含 im-ibus.so
  3. 確認二進位路徑（which）是 Snap、Flatpak 還是原生

環境變數正確不代表可用

GTK_IM_MODULE=ibus 設定正確，但如果程式載入的 GTK 函式庫找不到對應模組，設定就形同虛設。問題在函式庫層，不在環境變數。

Ubuntu 24.04 上 VS Code 的建議安裝方式： 使用 Microsoft 官方 apt repository（packages.microsoft.com/repos/code），而非 Ubuntu Snap Store 提供的版本。
